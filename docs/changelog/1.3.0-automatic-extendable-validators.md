# Automatic and extendable form validation

## What changed

- `Injectable\Validator` no longer hard codes the annotation map. An annotation
  name is converted to snake case and looked up on the shared
  `RuleRegistry`; the legacy `@Is*` names are kept as a fallback alias table.
  Every registered rule is therefore addressable by its canonical name, so
  `@MinLength(8)` becomes `min_length:8`, `@Between(1, 10)` becomes
  `between:1,10`, and a custom `phone` rule is addressable as `@Phone`.
- Added `Strukt\Framework\Contract\Validator`, an app facing contract that
  extends `Strukt\Rules\Contract\RuleInterface` and is constructed with the
  field name and its parameters.
- Added `Strukt\Framework\Extendables`, a single discovery pass over the
  application library (`lib/App`). It classifies each discovered class by the
  interface it implements — `Contract\Validator`,
  `Strukt\Contract\MiddlewareInterface`, or `Strukt\Contract\ProviderInterface`
  — derives the rule name from `@Name` (or the class short name), and registers
  custom rule factories on the shared registry.
- `Strukt\Framework\Application` runs `Extendables::discover()->register()`
  right after the autoloader is set up.
- `Strukt\Framework\Bootstrap` merges the discovered middlewares and providers
  with those configured in `cfg/module.ini` (deduplicated) and no longer bails
  out when a module has no configuration.
- Added the `validator:make` console command and `templates/validator.sgf`
  scaffold.

## Why

The previous map only covered ten rules through thirteen annotations, so more
than half of the built-in `strukt/rules` rules could not be used on a form and
custom rules were unreachable. Validators (and every other user extension
point) now live in the application library and are picked up automatically,
which removes the hard coded map and matches the "everything under `lib/App`"
layout.

## Documentation

- `src/Strukt/Framework/Injectable/Validator.php` class docblock rewritten to
  describe the automatic mapping and the alias fallback.
- `README.md` console table gained `validator:make`.

## Tests

- `tests/Unit/ValidatorMappingTest.php`: maps all 28 built-in rules, asserts the
  mapping covers the whole registry (`Rule::names()`), exercises the legacy
  aliases, and ignores non-rule annotations.
- `tests/Unit/ExtendablesTest.php`: discovers and registers an app validator,
  uses it from a form annotation end to end, and classifies middlewares and
  providers.
- `tests/Unit/ValidatorMakeTest.php`: scaffolds a validator file.
- Framework suite: 64 passed (187 assertions); lint clean.

## Public API impact

- **New:** `Strukt\Framework\Contract\Validator`, `Strukt\Framework\Extendables`,
  `Strukt\Framework\Console\Command\ValidatorMake`, and the `validator:make`
  command.
- Non-breaking: the `@Is*` annotations keep working; canonical `@Rule` names are
  added alongside them.
