# 1.7.0 — Route class prefixes via @Prefix

**Date:** 2026-10-20

**Changed**

- Added `@Prefix` support to `Strukt\Framework\Injectable\Router`: a class-level
  `@Prefix(/path)` annotation is prepended to every route declared on methods of
  that router, with join semantics matching `Strukt\Router\Router::group()`.
- `Injectable\Router` also loads a class from `Prefix.php` in the router class
  directory (via `prefix()`, `$prefix`, or `getPrefix()`) to apply a
  folder-level prefix to all routers in that folder. Class-level `@Prefix` takes
  precedence over `Prefix.php`.
- `Injectable\Router` now reads class-level notes from the annotation parser
  (already supported) and applies the normalized prefix to `route.path`.

**Why**

- Grouping routes required repeating a path prefix in every `@Route(...)`
  annotation. A router-class or router-folder prefix keeps the grouping unit
  declarative and single-sourced, matching the existing class-level annotation
  pattern (`@Name`).

**Documentation**

- `docs/routing.md`: added class-level and folder-level prefix sections and
  `@Prefix` to the annotations table.

**Tests**

- Added coverage for `@Prefix` on a router class (prepended paths, root route
  trailing slash, normalization).

**Public API impact**

- None. New optional class-level annotation and optional `Prefix.php` marker;
  existing routers unchanged.
