# 1.2.0 — Dependency injection container

## What changed

The framework now has a proper dependency container and its own collaborators
are composed through it, replacing the ad-hoc `new` and global lookups.

- Added `Strukt\Framework\Container\Container`, a PSR-11 container
  (`Psr\Container\ContainerInterface`) with `set()` (shared), `factory()`
  (transient), `instance()`, `alias()`, and a reflection-based `make()` that
  autowires constructor parameters by type.
- Added `Strukt\Framework\Container\ContainerException` and
  `Strukt\Framework\Container\NotFoundException` implementations of the PSR-11
  exceptions.
- Added `container()` helper returning the shared container. `helpers.php`
  wires `Kernel` (wrapped `RouterAdapter`), `Registrar`,
  `Configuration`, `ModuleStore`, and `PackageRepository` into it.
- Added ports `Strukt\Framework\Contract\ModuleStore` and
  `Strukt\Framework\Contract\PackageRepository` with adapters
  `Module\Storage\RegistryStore` (wraps `reg()`),
  `Module\Storage\MemoryStore` (in-memory, for tests), and
  `Package\ReposRepository` (wraps `Strukt\Package\Repos`).
- `Module\Registrar` now takes an injected `ModuleStore` and facet folder map,
  falling back to the globals. It no longer reads `reg()` or
  `config('module.folders')` directly.
- `Configuration` now takes injected `Cache`, application type, and
  `PackageRepository`, falling back to the globals. `create()` accepts an
  optional `PackageRepository` too.
- `Bootstrap::run()` resolves providers through the container when one is
  given.
- `Shell` builds command instances through a `Console\CommandFactory`
  (`PlainCommandFactory` or container-autowiring `ContainerCommandFactory`),
  instead of `new` in the dispatch loop.
- `Application::make()` composes kernel, registrar, and configuration from the
  shared container services.

## Why

The previous design leaned on hidden globals (`config()`, `reg()`, `cache()`)
and bare `new` calls, which made the framework hard to test in isolation and
hard to customise. Injecting ports with global defaults keeps behaviour
unchanged while making every collaborator replaceable.

## Documentation

- `README.md`: added a "Dependency injection" section describing the
  `container()` helper and the wiring of framework services.

## Tests

- Added `tests/Unit/ContainerTest.php`: PSR-11 conformance, shared/transient
  bindings, autowiring, named arguments, and PSR exception behaviour.
- Added `tests/Unit/RegistrarTest.php`: module discovery against an injected
  in-memory `ModuleStore`, isolation from the shared registry, and container
  resolution.
- Added `tests/Unit/ConfigurationTest.php`: discovery through an injected
  `PackageRepository` and a fully injected `Configuration`.

Suite now runs 30 tests / 63 assertions; `composer lint` is clean.

## Public API impact

- `composer.json` now requires `psr/container` (`^1.1 || ^2.0`).
- New public classes: `Container`, `ContainerException`, `NotFoundException`,
  `ModuleStore`, `PackageRepository`, `RegistryStore`, `MemoryStore`,
  `ReposRepository`, `CommandFactory`, `PlainCommandFactory`,
  `ContainerCommandFactory`.
- New public helper: `container()`.
- `Registrar::__construct(?ModuleStore $store = null, ?array $folders = null)`
  and `Configuration::__construct(?Cache $cache = null, ?string $appType = null,
  ?PackageRepository $packages = null)` — both remain callable with no
  arguments.
- `Application::make()` now resolves collaborators through the shared
  container; the router argument still overrides the container kernel.
