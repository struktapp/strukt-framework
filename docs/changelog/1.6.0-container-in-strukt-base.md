# 1.6.0 — Container moved to Strukt\Base and shared via app()

**Date:** 2026-10-15

**Changed**

- `Strukt\Framework\Container\Container`, `ContainerException`, and
  `NotFoundException` moved to `strukt/base` and are now
  `Strukt\Container\Container`, `Strukt\Container\ContainerException`, and
  `Strukt\Container\NotFoundException`. The framework imports were updated in
  `src/helpers.php`, `Bootstrap`, `Application`, and `ContainerCommandFactory`.
- The `container()` helper no longer keeps its own `static $singleton`. It now
  calls `Strukt\Container\Container::getInstance()` / `setInstance()`, so the
  framework shares one container with the low-level `app()` helper.

**Why**

- The container is a low-level primitive, but it lived at the top of the
  dependency graph. Moving it into `base` lets any package resolve `app()` and
  removes the split between the framework's container singleton and the
  `base`-level accessor.

**Documentation**

- `docs/dependency-injection.md`: updated the container FQCN, the import
  example, and documented that `app()` resolves against the same shared
  container.
- `README.md`: updated the dependency-injection import example.

**Tests**

- `tests/Unit/ContainerTest.php`: updated imports to `Strukt\Container\*`. The
  container behaviour tests moved to `strukt/base` alongside the class. The
  remaining framework tests (89) pass unchanged.

**Public API impact**

- Breaking: `Strukt\Framework\Container\*` no longer exists; use
  `Strukt\Container\*`. `container()` keeps its signature and behaviour but is
  now backed by the container's own shared instance.
