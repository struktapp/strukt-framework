# 1.7.0 Rename Repos and repository classes

## What changed
- `Strukt\Bundle\Repos` → `Strukt\Bundle\Bundles` (the static registry).
- `Strukt\Framework\Bundle\ReposRepository` → `Strukt\Framework\Bundle\BundlesRepository`.
- `Strukt\Framework\Contract\BundleRepository` → `Strukt\Framework\Contract\BundlesRepositoryInterface`.

## Why
- `Repos` / `ReposRepository` / `BundleRepository` read as redundant and unclear next to the
  `Bundle`/`bundles` vocabulary introduced by the package → bundle rename. The plural
  `Bundles` naming makes the registry and the port line up with the rest of the API, and the
  `Interface` suffix makes the contract explicit.

## Documentation touched
- `README.md`, `docs/bundles.md`, `docs/architecture.md`, `docs/dependency-injection.md`,
  `docs/helpers.md`, `docs/console.md`, `docs/configuration.md`.

## Tests added or updated
- `tests/Unit/ConfigTest.php`, `tests/Unit/ConfigurationTest.php` (stub now implements
  `BundlesRepositoryInterface`).

## Public API impact
- Breaking: `Strukt\Bundle\Repos` → `Strukt\Bundle\Bundles`, static methods `available()` /
  `bundles()` unchanged.
- Breaking: `Strukt\Framework\Contract\BundleRepository` → `BundlesRepositoryInterface`;
  the container binds the interface to `BundlesRepository`.
