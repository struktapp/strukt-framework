# Restore the package publisher scaffolding commands

## What changed

Three commands from strukt1 were brought back behind the Package Publisher
console section:

- `package:make <name>` scaffolds a package descriptor based on the shipped
  `templates/package/Pkg_.sgf`, generating `src/Strukt/Package/Pkg<Name>.php`
  and a `package.json` manifest when missing.
- `package:add <folder>` records a folder's files (or a single file) in
  `package.json` under their root-relative paths, deduplicating entries.
- `package:export <name>` assembles a distributable `pkg-<name>` folder with
  the `package/` assets, the descriptor class, `.env`/`.gitignore`, and a new
  `composer.json` plus `README.md`.

The `cfg/cmd.ini` `[pub-pak]` section now lists all five package commands.

## Why

`route:ls`/`app:exec` proved the tooling restoration effort by making a
generated app introspectable and servable. The package publisher suite is the
next strukt1 behaviour gap: its section existed in `cmd.ini` but only two of
the eight commands were implemented.

## Documentation

- `README.md`: Package Publisher command table extended with `package:make`,
  `package:add`, and `package:export`.

## Tests

- `tests/Unit/PackageCommandTest.php` added: scaffolding and manifest creation,
  the already-exists branch, folder and single-file manifest additions, and
  the export folder layout.

## Public API impact

- None. New commands extend the framework console surface.
