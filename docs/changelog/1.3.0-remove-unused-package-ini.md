# Remove the unused `package` config section

## What changed

Deleted `cfg/package.ini` and dropped its entry from the shipped-sections
documentation. The file declared two sections — `auth` and `db`, each with a
`default` driver and a `home[]` list (`pop-db`, `red-db`) — that no strukt4 code
ever read.

The shared registry no longer exposes a `package` config section, so the
`expect(config('package'))->toBeArray()` assertion was removed from
`tests/Unit/ConfigTest.php`.

## Why

`package.ini` was carried over verbatim from `strukt1/strukt-framework` during
the port. In strukt1 the old `PackageDiff` and `PackagePublisher` read
`config("package")` to choose a package's default folder variant and strip its
prefix when publishing files. The equivalent strukt4 publisher commands
(`package:make`, `package:add`, `package:export`, `package:ls`, `package:info`)
resolve through `cfg/repo.ini` instead and never touch the section. Its values
named variants (`pop-db`, `red-db`) of `auth`/`db` packages that do not exist in
strukt4, so the file advertised a feature that was not ported.

A redesigned section will be reintroduced alongside the package publisher port
(`package:copy` / `package:diff` / `package:publish`) if those commands need
per-package variant metadata.

## Documentation

- `README.md`: removed the `package` row from the shipped configuration table.
- `docs/configuration.md`: removed the `package.ini` table row and its
  `### package.ini` subsection.

## Tests

- `tests/Unit/ConfigTest.php`: dropped the `config('package')` assertion from
  the cfg-sections test; the remaining sections (`cmd`, `module`, `cache`,
  `repo`) are still asserted.

## Public API impact

`config('package')` is no longer populated. The section had no runtime reader
within the framework or any strukt4 package, so no behavior changes; only code
that explicitly queried `config('package')` would notice.
