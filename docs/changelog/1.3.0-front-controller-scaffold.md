# 1.3.0 — app:reload and app:exec scaffold the front controller too

## What changed

The front controller (`index.php`) was only generated by `app:make`. Running
`app:reload` + `app:exec` on a project without the `app:make` scaffold left the
project without an entry script, so `app:exec` fell back to a bare
`php -S -t <root>` and every request returned *not found*.

`Reloader::ensureFrontController(string $root)` now copies the shipped
`templates/app/index.php` into the project root when none exists, and both
`app:reload` and `app:exec` call it (echoing `Front controller generated.` the
first time). An existing `index.php` is never overwritten, so custom front
controllers survive.

## Why

The `app:reload -> app:exec` flow is the documented bootstrap, but the reload
step only produced the loader and `.env`. The scaffold is now self-sufficient:
reload guarantees the pieces a server actually needs — entry script, module
loader, environment.

## Documentation

- `README.md`: "Serving the application" updated to note that `app:reload` and
  `app:exec` scaffold a missing front controller, `.env`, and loader.

## Tests

- `tests/Unit/ReloaderTest.php`: `app:reload` creates `index.php` on first run
  and leaves a user-written front controller untouched on later runs.

## Public API impact

- `Reloader` gains `ensureFrontController(string $root): bool`; constructor and
  `__toString()` unchanged.
- `app:reload`/`app:exec` emit a `Front controller generated.` notice on first
  creation.
