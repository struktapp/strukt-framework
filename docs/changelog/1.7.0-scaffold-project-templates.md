# 1.7.0 — Project-owned scaffolding templates

**Date:** 2026-10-19

**Changed**

- Added `Strukt\Framework\Templates` with `defaults()`, `dir()`, `path()`,
  `ensure()`, and `install()`. `path()` resolves a template project-first
  (`<root>/templates/<relative>`) then framework-first
  (`templates/<relative>`); `ensure()` copies the framework templates the
  project is missing without overwriting; `install()` maps a template path onto
  its destination, expanding `{{...}}` placeholders and resolving the `lib/App`
  and `app/src` prefixes against `rel_app_lib` and `rel_appsrc`.
- Reorganised `templates/` so **each template lives at its install path** with
  only the extension changed: `middleware.sgf` → `lib/App/Middleware/{{class_name}}.sgf`,
  `facet.sgf` → `lib/App/Provider/Facet.sgf`, `loader.sgf` → `lib/App/Loader.sgf`,
  `bundle/Bundle_.sgf` → `src/Strukt/Bundle/Bundle{{class_name}}.sgf`,
  `app/index.php` → `index.php`, and `app/cfg/*.sgf` → `cfg/*.sgf`. The unused
  `router.sgf` was dropped.
- `app:make` scaffolds the project's `templates/` set before rendering, renders
  `app/src/**` sources from `templates/app/src/**`, scaffolds the front
  controller, and resolves through `Templates::install()`; `app:reload`
  backfills the set and reports `Templates generated: N file(s).`.
- Every generator resolves templates through `Templates`: `middleware:make`,
  `provider:make`, `validator:make`, `bundle:make`, the loader
  (`Reloader`), the front controller, and the facet provider. `rel_loader_sgf`
  still takes precedence for the loader.

**Why**

- Templates were shipped only with the framework, so projects could not
  customise generated code — the same asymmetry the `cfg/` scaffolding fixed.
  Project-owned templates make scaffolding editable while the framework copies
  remain the fallback.
- Mirroring the install path makes the destination of every template obvious at
  a glance and lets placeholder expansion happen once, in both path and content.

**Documentation**

- Added `docs/templates.md` (layout table + resolution order); linked it from
  `docs/README.md` and referenced it from `docs/console.md`,
  `docs/extensions.md`, and `docs/getting-started.md`.

**Tests**

- `tests/Unit/TemplatesTest.php`: covers `ensure()` copying and not
  overwriting, project-first `path()` resolution, `install()` path mapping, and
  `middleware:make` generating from a customised project template.
- `tests/Unit/ReloaderTest.php`: `app:reload` scaffolds the templates and never
  overwrites them.

**Public API impact**

- New class `Strukt\Framework\Templates`. `app:make`/`app:reload` write a
  `templates/` directory; generator output can now come from project templates.
  The framework `templates/` tree layout changed, but it is internal scaffolding
  input, not a public API.
