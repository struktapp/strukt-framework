# 1.3.0 — Console commands organised into sections

## What changed

The framework `list` output is now driven by the sections configured in
`cfg/cmd.ini`, restoring the strukt1 behaviour of grouping commands under
headings.

- `CommandRepository::sections()` maps each `cmd` configuration section onto
  the discovered `CommandDefinition` instances, preserving the configuration
  order. A section resolves to the definitions of its `cmd[]` names and may
  carry a `title` heading (`[main]` has none; `[pub-pak]` renders
  "Package Publisher"). Sections that resolve to no commands are skipped, and
  commands that are discovered but not configured anywhere are appended under a
  final unlabelled group so the list always stays complete.
- `Shell` renders `list` / `commands` and a bare `help` through the new
  sectioned renderer instead of the flat alphabetical one.

```text
Available commands:

  app:make   Generate application scaffolding
  ...

Package Publisher

  package:ls   List packages and their status
  package:info Show information on a package
```

## Why

strukt1 presented commands in labelled sections defined by `cfg/cmd.ini`
(`title` + `cmd[]`). The remake discovered commands flat and ignored the
sections, hiding the structure applications relied on to group their CLI.

## Documentation

- `README.md`: the console commands table was split to keep the same layout
  users now see — main commands first, then the package publisher section.

## Tests

- `tests/Unit/ShellTest.php`: asserts `list` places `app:make` before the
  `Package Publisher` heading and `package:info` after it.

## Public API impact

- New public method: `CommandRepository::sections(): array`, returning
  `list<array{title: string|null, commands: list<CommandDefinition>}>`.
- `CommandRepository::all()` and the flat `Renderer::list()` remain available.
- Depends on `strukt/console` providing `Renderer::sections()`.
