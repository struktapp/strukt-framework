# 1.0.0 — Initial release

Modern, full port of `strukt1/strukt-framework` onto the `strukt4` package set.

## What changed

- Ported the framework kernel, facades, contracts, injectables, traits,
  helpers, console shell, and package metadata to `Strukt\Framework\` (and the
  shared `Strukt\` helpers) in a new package `strukt/framework`.
- `Application` now drives the modern `strukt/router` `Router` (final class):
  modules register routes through the fluent verb methods, and `init()`/
  `run()`/`handle()` replace the old kernel dispatch.
- `Shell` was rewritten as a discovery + docblock pipeline on top of
  `strukt4/console` (`DocBlockParser`, `CommandDiscovery`, `CommandInterface`,
  `Renderer`), lifting the framework commands into annotation-defined command
  classes.
- `Annotation\Parser` was ported from `strukt1/strukt-generator`, preserving the
  legacy `getNotes()` shape (`class_name`, `class`, `properties`, `methods`).
- `Strukt\Entity` and `Strukt\Package\{Core,Repos}` provide the legacy entity
  and package registry behavior in the `strukt` namespace.
- Defects from the original framework were fixed: `register()` deduplication now
  compares namespaces, `Configuration::create()` no longer merges recursively,
  and `package()->get('commands'|'cmd')` returns commands instead of
  middlewares.
- Added command scaffolding templates (`templates/*.sgf`) and an application
  loader (`Reloader`).

## Documentation

- Added `README.md` (installation, quick start, configuration, command list).

## Tests

- Added Pest suite under `tests/Unit` covering the annotation parser, `Entity`
  positional assignment, the framework `cfg` loading and package registry,
  `Application` module/route registration, and the `Shell` console.

## Public API impact

- New package `strukt/framework`; new namespace `Strukt\Framework\` and shared
  helpers `repos()`, `core()`, `package()`, `validator()`, `hashfn()`.
- `config()` follows the `strukt4/commons` dot-path semantics; framework `cfg`
  sections are merged into the shared registry per section when unset.
- Route, form, and middleware annotations keep the legacy syntax; routes are now
  registered against the `strukt4` router.
