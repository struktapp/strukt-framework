# route:make command

## What changed

- Added the `route:make` console command. It generates a module router, or
  appends a route method to an existing one, writing to
  `app/src/<App>/<Module>/<rtr>/<Name>.php`.
- The command is hybrid: values may be passed as `<module> <name> <route>` with
  `--method`, `--permission`, and `--function` options, or omitted and answered
  interactively. Outside an interactive terminal a missing argument raises
  instead of blocking.
- Route placeholders are emitted as typed parameters (`{id:int}` -> `int $id`),
  and each generated method carries `@Method`, `@Route`, and optional
  `@Permission` annotations and a `Strukt\Contract\Http\RequestInterface`
  parameter.
- Corrected `templates/router.sgf`: the request parameter is now typed against
  `Strukt\Contract\Http\RequestInterface` (the concrete `Strukt\Http\Request`
  did not satisfy the invoker's interface-based resolution).
- Registered the command in `cfg/cmd.ini` and the README command list.

## Why

Porting the strukt1 `route:make` command completes the scaffolding set. The
strukt1 command was purely interactive while the strukt4 console is
non-interactive, so the port supports both argument-driven and interactive use.

## Documentation

- `docs/routing.md`: new "Scaffolding routes" section.
- `docs/console.md`: `route:make` added to the section config and command table.
- `README.md`: `route:make` added to the console command list.

## Tests

- `tests/Unit/RouteMakeTest.php` (7 tests): create, append, typed placeholders,
  permission annotation, explicit function name, unknown module, and the
  non-interactive missing-argument guard.

## Public API impact

- New command `route:make`. No changes to existing classes or interfaces.
