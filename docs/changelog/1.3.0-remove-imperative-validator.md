# Remove the dormant imperative validator stack

## What changed

The legacy imperative validation API was deleted because nothing consumed it:

- Removed `Strukt\Framework\Traits\Validator` (the `isAlpha`, `isEmail`, …
  boolean-check trait).
- Removed `Strukt\Framework\Contract\Validator` (its abstract base holding the
  `$message` result bag).
- Removed `Strukt\Framework\Provider\Validator` (the `provider.validator`
  event emitter).
- Removed the `validator()` helper from `src/helpers.php`.
- Dropped the `valid` **provider** entry from `Strukt\Package\Core`. The
  `valid` **middleware** (`Strukt\Framework\Middleware\Validator`) is kept: it
  remains the no-op `valid` alias for annotated routes.
- Removed the now-empty `src/Strukt/Framework/Provider/` directory.
- Updated `tests/Unit/ConfigurationTest.php`, which asserted the removed
  provider was discovered.

## Why

Validation in strukt4 flows through one path: a route form typed as
`Strukt\Contract\FormInterface`, whose framework base
(`Strukt\Framework\Contract\Form`) compiles property annotations through
`Injectable\Validator` into `strukt/rules` rule strings, resolved by the router
`Invoker`. The imperative trait/contract/provider/helper stack duplicated those
same conditions (`alpha`, `numeric`, `email`, `date`, `required`, `in`, `same`,
`length`) with no caller: no `App\Validator` is scaffolded, `validator()`
raised without one, and nothing listened to `provider.validator`. Keeping it
also risked drift, since `Traits\Validator::isAlpha()` accepted underscores
while the `alpha` rule is letters-only.

## Documentation

- None; no documentation referenced the removed API.

## Tests

- `tests/Unit/ConfigurationTest.php` updated to assert provider discovery
  generically and to check a kept middleware. Full framework suite: 59 passed.

## Public API impact

- **Breaking:** `Strukt\Framework\Traits\Validator`,
  `Strukt\Framework\Contract\Validator`,
  `Strukt\Framework\Provider\Validator`, and the `validator()` helper are
  removed. Callers should use `strukt/form` with the `strukt/rules` engine
  (annotated forms or `form_check()`).
