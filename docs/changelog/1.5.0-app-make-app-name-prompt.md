# Prompt for the application name in `app:make`

## What changed

- `app:make` now prompts for the application name when the `<app_name>` argument
  is omitted, mirroring `route:make`. The argument stays supported and is used
  as-is when provided.
- The prompt reads from the controlling terminal: it prefers standard input when
  it is a terminal, and otherwise opens `/dev/tty`. This keeps the prompt visible
  and functional when the output is captured, such as inside Composer's
  `post-create-project-cmd` hook during `composer create-project`. When no
  terminal is available the command fails with
  `Application name is required when not running interactively.`
- Camel-casing of the name now also splits on spaces and hyphens (not just
  underscores), so an interactively typed `Demo App` becomes `DemoApp` instead of
  producing an invalid `Demo App` namespace.

## Why

The `strukt/strukt` skeleton install hook ran `app:make Web`, hardcoding the
application name. Prompting makes `composer create-project` ask for the name
instead of always scaffolding a `Web` application.

## Documentation

- `docs/console.md`: `app:make` usage is now `app:make [<app_name>]`, with a note
  on the prompt and the non-interactive failure.
- `docs/getting-started.md`: notes that the name may be omitted and that spaced,
  underscored, and hyphenated names are camel-cased.

## Tests

- `tests/Unit/AppMakeTest.php`: added coverage that spaced and hyphenated names
  (`pay roll-two`) camel-case to `PayRollTwo`. The existing argument-based and
  underscore cases continue to pass. The interactive prompt is validated manually
  over a pseudo-terminal (it is avoided in the suite to prevent blocking on CI's
  accepted non-tty convention).

## Public API impact

- `app:make`'s `<app_name>` argument is no longer required; the command gains an
  interactive prompt. No new classes or signatures.
