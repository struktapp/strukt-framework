# 1.7.0 — Generate the bundle-db cmd section only with Strukt Ar

**Date:** 2026-10-20

**Changed**

- `templates/cfg/cmd.sgf` now guards its `[bundle-db]` group (`model:generate`,
  `db:create`) with `{if bundle_db} … {/if}`.
- `Reloader::ensureConfigs()` renders `cfg/*.ini` templates with a new
  `bundle_db` value, set from `class_exists(\Strukt\Ar\Model::class)`.

**Why**

- The `model:generate` and `db:create` commands are `ConditionalCommand`s that
  only run when Strukt Ar is installed, but the generated `cfg/cmd.ini` still
  advertised a `[bundle-db]` section for every project. Generating the section
  only when the package is present keeps the scaffolded config truthful —
  projects that later install `strukt/ar` or `strukt/orm` pick the section up
  on the next `app:reload` (which backfills the file only when it is missing).

**Documentation**

- `docs/console.md`: notes that a section resolving to no commands is skipped,
  and that `[bundle-db]` is conditional.
- `docs/configuration.md`: `cmd.ini` section note.
- `docs/templates.md`: the `bundle_db` render value and the guarded group.

**Tests**

- `tests/Unit/ReloaderTest.php`: asserts `cfg/cmd.ini` omits `[bundle-db]` while
  Strukt Ar is absent, and that the template renders the group when `bundle_db`
  is true. The generated-config comparison now renders the template the same
  way production does.

**Public API impact**

- None. The generated `cfg/cmd.ini` for a project without Strukt Ar no longer
  contains the `[bundle-db]` section.
