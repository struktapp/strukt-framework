# xhttp profiles in cfg/xhttp.json

## What changed

- Removed the `--session key=value` command-line option from `bin/xhttp`; session
  values and credentials are no longer passed on the command line.
- Added `cfg/xhttp.json` profile support. A profile is a named entry holding a
  `session` map (seeded before dispatch) and a `data` map (merged into the request
  fields — query for `GET`/`HEAD`, body otherwise). Profiles are selected with the
  new `--as <profile>` option.
- Added `Xhttp::profile(string $name, string $file): array`, which loads and
  validates a named profile and raises when the file is missing, malformed, or the
  profile is absent/not an object.
- The binary now refuses common secret field names (`password`, `passwd`, `pwd`,
  `pass`, `secret`) as `key=value` arguments, pointing the caller at
  `cfg/xhttp.json` and `--as` instead.
- Command-line `key=value` fields override matching profile `data` fields.
- Updated `Xhttp::help()` and the binary usage text.

## Why

Passing session values (impersonation) and passwords on the command line leaks
them into shell history and process listings. Profiles keep both in
`cfg/xhttp.json`, selected by name, and the binary rejects obvious secrets typed
at the prompt.

## Documentation

- `docs/xhttp.md`: rewrote Usage, added a "Profiles" section with an example
  `cfg/xhttp.json`, replaced the session-seeding examples with `--as`, and
  documented the secret guard and `Xhttp::profile()`.

## Tests

- `tests/Unit/XhttpTest.php` (12 tests): added profile loading (session + data),
  missing file, unknown profile, and an in-process test that seeds the profile
  session and merges its data; added binary tests for the command-line secret
  guard and a missing `--as` profile. Updated the help assertions.

## Public API impact

- New static method `Strukt\Framework\Console\Xhttp::profile()`.
- `bin/xhttp`: `--session` removed, `--as` added, secret arguments refused.
