# 1.7.0 — Load the project cfg files

**Date:** 2026-10-19

**Changed**

- Added `Strukt\Framework\ConfigLoader` with `load(string $root): array` and
  `root(): string`. `load()` merges the project's `<root>/cfg/*.ini` sections
  over whatever defaults are already in the config registry, preserving keys the
  project does not override.
- `Shell::run()` and `Application::make()` call it during bootstrap, so the
  console and the HTTP entry point both honour the project's configuration.

**Why**

- The config registry only ever read the INI files shipped by packages: the
  framework's own `cfg/`, plus `app.ini` from `strukt/commons`. The project's
  `cfg/` directory was inert — `config('app.middlewares')` and
  `config('app.providers')` (used by `Injectable\Facet`) always returned `null`,
  and edits to `cmd.ini`, `module.ini`, and `repo.ini` had no effect. Loading
  the project copy makes those files authoritative while keeping dependency
  defaults such as `app.name`.

**Documentation**

- `docs/configuration.md`: the config registry section now describes the
  package-default and project-override layers and when `ConfigLoader` runs.

**Tests**

- `tests/Unit/ConfigLoaderTest.php`: covers merging over an existing section,
  loading every INI file in `cfg/`, the no-`cfg`-directory no-op, and root
  resolution.

**Public API impact**

- New class `Strukt\Framework\ConfigLoader`. Project `cfg/*.ini` values now
  override framework defaults at runtime; applications relying on the framework
  copy for a section they also ship under `cfg/` will now see their own values.
