# 1.3.0 — Runtime app autoloader and front controller for app:exec

## What changed

`app:exec` can now actually serve a generated application on the built-in
server. Previously it only ran `php -S host:port -t <root>`, which 404'd: the
scaffold wrote no entry script and neither `lib/App/Loader.php` (namespace
`App`) nor `app/src/<App>/...` (namespace `<App>`) was autoloadable.

Three pieces landed:

1. **`Strukt\Framework\Autoload`** registers runtime PSR-4 autoloaders mapping
   `App\` -> `<root>/<rel_app_lib>` and, per first-level directory under
   `<root>/<rel_appsrc>`, `<App>\` -> `<root>/<rel_appsrc>/<App>/`. No composer
   autoload edits or `composer dump-autoload` are required. It re-registers
   when the project root changes and is idempotent for a given root.
   `Application::make()` and `bin/strukt` both call `Autoload::register()`.
2. **`templates/app/index.php`** is scaffolded by `app:make` into the project
   root. It loads the composer autoloader, registers the app autoloader, then
   builds the application through `App\Loader` (falling back to
   `Application::make()`) and runs it. Under the built-in server it doubles as
   the router script, returning `false` only for real, non-PHP assets so
   `.php` sources are never served raw.
3. **`AppExec`** appends `<docroot>/index.php` as the router script when it
   exists (`php -S host:port -t <docroot> <docroot>/index.php`), falling back
   to the plain `-t` invocation for projects without a front controller.

## Why

The remake stopped at scaffolding modules; nothing wired them into a runnable
web entry. strukt1 relied on the consuming project shipping an `App\` composer
mapping and its own `index.php`. Shipping the autoloader and front controller
in the framework makes a scaffolded project servable out of the box.

## Documentation

- `README.md`: new "Serving the application" section covering
  `app:make`/`app:reload`/`app:exec` and runtime autoloading.

## Tests

- Added `tests/Unit/AutoloadTest.php`: resolves `App\Loader`, `<App>\User`, and
  nested `<App>\Router\Index` without composer autoload; re-registration is
  idempotent.
- Added `tests/Unit/AppExecTest.php`: `AppExec::command()` passes the front
  controller as the router script when `index.php` exists and omits it
  otherwise.
- `tests/Unit/AppMakeTest.php`: asserts `index.php` is scaffolded with the
  front-controller plumbing.

## Public API impact

- New public class `Strukt\Framework\Autoload` with `register(?string $root)`
  and `reset()`.
- `AppExec` gains a public static `command(string $host, string $port, string
  $context): string` for testability.
- Scaffolded apps gain a root `index.php`; regenerating an existing app after
  this change requires removing the old `app/src/<App>` directory.
