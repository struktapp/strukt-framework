# 1.3.0 — app:reload and app:exec scaffold a default .env

## What changed

`Strukt\Framework\Environment::ensure(string $root)` creates `<root>/.env`
with the framework's default keys when none exists:

```text
serve_host = 127.0.0.1
serve_port = 8080
serve_ctx = .
is_dev = true
rel_appsrc = app/src
rel_app_lib = lib/App
rel_mod_ini = cfg/module.ini
```

`app:reload` and `app:exec` (before the built-in server boots) call
`Environment::ensure()` and report `.env generated.` on first creation. An
existing `.env` is never touched, so project overrides survive.

`root_dir` is intentionally omitted: it is the shell working directory for
`bin/strukt` and the web document root for the built-in server, so baking an
absolute path into the scaffold would make it fragile.

## Why

A scaffolded project had no `.env`, and `bin/strukt` already prefers a `.env`
file over its built-in defaults when one exists. Generating it from the app
commands gives users the common knobs (`serve_port`, `serve_ctx`, ...) in one
editable place without requiring manual setup.

## Documentation

- `README.md`: "Serving the application" now notes that `app:reload` and
  `app:exec` scaffold a `.env` with the defaults.

## Tests

- Added `tests/Unit/EnvironmentTest.php`: ensures the default file is created
  exactly once and never overwrites an existing `.env`.
- `tests/Unit/ReloaderTest.php`: `app:reload` generates `.env` and echoes the
  notice.

## Public API impact

- New public class `Strukt\Framework\Environment` with `ensure(string $root):
  bool` and `file(string $root): string`.
- `app:reload` and `app:exec` emit a `.env generated.` notice on first run.
