# Add the framework backlog document

## What changed

Added [`docs/BACKLOG.md`](../BACKLOG.md), a single place to track work that is
planned or outstanding for `strukt/framework`. The file name is uppercase by
convention. It currently records the strukt1 console commands that have no
strukt4 equivalent yet:

- `package:publish` (`PackagePublisher`)
- `package:copy` (`PackageCopy`)
- `package:diff` (`PackageDiff`)
- `sys:util` (`SysUtil`)

plus the follow-up to reintroduce a redesigned `cfg/package.ini` if those
commands need per-package variant metadata.

The document is indexed from `docs/README.md` (a new "Project" table) and
listed in the top-level `README.md` documentation section.

## Why

The port from `strukt1/strukt-framework` is not finished, but the remaining
work only lived in the changelog (which records what *shipped*) and in
conversation. A dedicated backlog makes the gap explicit and gives future work
a home that is distinct from the release record.

## Documentation

- `docs/BACKLOG.md` added.
- `docs/README.md`: intro sentence and a "Project" index table now link it.
- `README.md`: the documentation list now points at the backlog.
