# Form annotations compile against the strukt/form engine

## What changed

The framework form path was exercised end to end against `strukt/form` and
`strukt/rules`:

- Fixed a null-coalescing gap in
  `src/Strukt/Framework/Injectable/Validator.php`: a property carrying no
  annotations surfaced as `null` and made `getRules()` emit a `foreach` warning
  on every validation. Values are now iterated through `(array)`.
- Added `tests/Unit/FormTest.php` covering the contract: property annotations
  compile to `required|alpha`-style rules, submissions validate through the
  `strukt/rules` engine, failures report per field, and the generated form
  simultaneously satisfies `Strukt\Framework\Contract\Form`,
  `Strukt\Form\Form`, and `Strukt\Contract\FormInterface`.

## Why

The generated `Form/User.php` and `Contract\Form` base extend the `strukt/form`
definition, but nothing verified the compiled rules actually resolve in the
`strukt/rules` registry, and the annotation validator warned on every uncover
property field.

## Documentation

- None; no API surface changed.

## Tests

- `tests/Unit/FormTest.php` added (four cases, one a regression for the null
  annotation warning). Full framework suite now 59 passed.

## Public API impact

- None. The validator fix only removes the spurious warning.
