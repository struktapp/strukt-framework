# 1.7.0 — Scaffold the facet provider with the loader

**Date:** 2026-10-17

**Changed**

- Added `templates/lib/App/Provider/Facet.sgf`, the source of the `App\Provider\Facet`
  provider that owns the `provider.core` event. It resolves an alias through
  `FacetHelper::getNamespace()` and the container (`container()->make()`).
- Added `Reloader::ensureFacetProvider(string $root): bool`, which writes
  `lib/App/Provider/Facet.php` from the template when the file is missing.
- `app:reload` now calls `Reloader::ensureFacetProvider()` after writing the
  loader and reports `Facet provider generated.`.

**Why**

- `core()` and `Core::get()` resolve facets through the `provider.core` event,
  which the `facet` provider owns, but generated applications never received
  that provider. Creating it alongside the loader wires facet resolution into
  every scaffolded app without manual setup.

**Documentation**

- `docs/console.md`: `app:reload` description now mentions the scaffolded facet
  provider.

**Tests**

- `tests/Unit/ReloaderTest.php`: added a test asserting `app:reload` writes a
  lintable `lib/App/Provider/Facet.php`, registers `provider.core`, and never
  overwrites an existing file. The framework suite (90 tests) passes.

**Public API impact**

- New static method `Reloader::ensureFacetProvider()`. `app:reload` writes one
  additional file; its exit code and existing outputs are unchanged.
