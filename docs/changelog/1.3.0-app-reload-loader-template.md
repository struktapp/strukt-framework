# 1.3.0 — app:reload renders the module loader from the shipped template

## What changed

`Strukt\Framework\Reloader` no longer requires a `rel_loader_sgf` environment
key pointing at an external `.sgf` template that no binary ever set. The loader
template now ships with the package at `templates/loader.sgf` and is used by
default; a custom path may still be supplied through the optional
`rel_loader_sgf` environment key, restoring strukt1's override point without
making it a hard requirement.

The generated `App\Loader` now targets the strukt4 API:

```php
final class Loader
{
    private Application $app;

    public function __construct(?Router $router = null)
    {
        $this->app = Application::make($router);
        $this->app->register(new \Payroll\AuthModule\PayrollAuthModule());
    }

    public function getApp(): Application
    {
        return $this->app;
    }
}
```

Also fixed a path-join bug introduced in the port: the per-app directory scan
built `<appsrc>` + `<app>` with no separator, so `app/src` + `Payroll` became
`app/srcPayroll` and no module was ever discovered.

## Why

The port copied the strukt1 reloader verbatim, but struk1 looked the template
up through an environment key that the remake's `bin/strukt` never sets, so
`app:reload` always failed with `File [] was not found!`. The remake also
changed `Fs::ds()` semantics from "path + trailing separator" to "normalize
slashes only", silently breaking module discovery.

## Documentation

- `README.md`: environment table gains the optional `rel_loader_sgf` override
  row.

## Tests

- Added `tests/Unit/ReloaderTest.php`: renders one `register()` call per
  `*Module` directory and ignores non-directory entries, honours a custom
  template via `rel_loader_sgf`, fails on a missing application source path,
  and writes a PHP-lint-clean `lib/App/Loader.php` through the `app:reload`
  command.

## Public API impact

- `Reloader` constructor signature unchanged; `__toString()` unchanged.
- `rel_loader_sgf` changes from required to optional.
