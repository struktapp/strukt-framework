# 1.7.0 — Scaffold the full project cfg set

**Date:** 2026-10-19

**Changed**

- Added `Reloader::ensureConfigs(string $root, ?string $app = null): array`,
  which renders a project's `cfg/*.ini` files from the matching
  `templates/cfg/*.sgf` templates when a file is missing, never
  overwriting an existing one. `app.ini` is only backfilled when an
  application name is resolvable (`ConfigLoader::app()`), so a blank-named
  config is never fabricated.
- Added `templates/cfg/{cache,cmd,module,repo}.sgf`, one template per
  generated config section, alongside the existing `app.sgf`.
- Added `ConfigLoader::app()`, which resolves the application name from
  `config('app.name')` then the project's `cfg/app.ini`.
- `app:make` now calls it after rendering the app templates, so a new
  application receives `app.ini`, `cache.ini`, `cmd.ini`, `module.ini`, and
  `repo.ini`. It reports `Configs generated: ...`.
- `app:reload` backfills the same files, mirroring how it already ensures
  `.env`, `index.php`, and the facet provider.

**Why**

- Generated applications only received `cfg/app.ini`, so the remaining sections
  were read from the framework copy and could not be edited per project.
  `rel_mod_ini` even pointed at a `cfg/module.ini` that did not exist. Copying
  the defaults gives each project an editable, self-contained `cfg/` set while
  `app:reload` upgrades projects scaffolded before a section existed.
- Generating from templates rather than copying the framework `cfg/*.ini` makes
  each project's files independent of the framework defaults: a section can be
  shaped for new (or backfilled) projects by editing its template, without
  touching the framework's own fallback config.

**Documentation**

- `docs/console.md`: `app:make`/`app:reload` descriptions and a note on the
  scaffolded `cfg/` set.
- `docs/configuration.md`: the shipped sections are documented as generated
  from `templates/cfg/*.sgf`.
- `docs/templates.md`: the `cfg/` template set.

**Tests**

- `tests/Unit/ReloaderTest.php`: asserts `app:reload` writes every config from
  its template, backfills `app.ini` when a name is known, and never overwrites
  an existing file.

**Public API impact**

- New static method `Reloader::ensureConfigs()` (now takes an optional app
  name) and `ConfigLoader::app()`. `app:make` and `app:reload` write additional
  files; exit codes and existing outputs are unchanged apart from the new
  `Configs generated: ...` line.
