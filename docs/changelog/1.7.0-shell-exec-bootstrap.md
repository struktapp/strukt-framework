# 1.7.0 — Boot the application in `shell:exec`

**Date:** 2026-10-17

**Changed**

- `Strukt\Framework\Console\Command\ShellExec` now boots the application before
  opening the PsySH session. It registers the autoloader, loads `App\Loader`
  (falling back to `Application::make()`), and calls `Application::init()`
  before building the `core` accessor.

**Why**

- `shell:exec` resolved facets through the `provider.core` event, but the
  console binary never called `Application::init()`. No providers were
  registered and the `nr.<alias>` registry was never populated, so
  `core('au.ctr.User')` raised
  `The [provider.core] provider is not registered.` Booting the app first wires
  the providers and indexes the facets, matching the web entrypoint and the
  existing `route:ls` command.

**Documentation**

- `docs/console.md`: `shell:exec` description now notes it boots the app first.
- `docs/routing.md`: documented that `core()` needs an initialized application
  and that `shell:exec` does it.

**Tests**

- Covered manually against the `strukt4/strukt` skeleton: from the shell,
  `reg('nr.au.ctr.User')` resolves to `Web\AuthModule\Controller\User`. The
  framework suite (89 tests) passes unchanged.

**Public API impact**

- None. `shell:exec` keeps its signature; it now initializes the application as
  a prerequisite for facet resolution.
