# Strukt Ar model commands in the framework console

## What changed

- Added `Strukt\Framework\Console\Command\ModelGenerate` (`model:generate`) and
  `Strukt\Framework\Console\Command\DbCreate` (`db:create`), which bridge to the
  matching `Strukt\Generate\Command\*` commands shipped by `strukt/ar`.
- The bridge defaults are application-aware: `--namespace` defaults to the
  application root namespace (the first-level directory under `rel_appsrc`, which
  the runtime autoloader also maps) and `--dir` defaults to that directory,
  instead of Ar's standalone `App\Model` / `build/Models`.
- Added `Strukt\Framework\Console\ConditionalCommand`. `CommandRepository::all()`
  now skips any command implementing it whose static `isAvailable()` returns
  `false`, so the Ar commands only appear (and only dispatch) when
  `strukt/ar` is installed.
- Added a `Strukt\Framework\Console\ArCommandSupport` trait holding
  `isAvailable()` (checks `class_exists(\Strukt\Ar\Model::class)`) and the
  namespace/directory default resolution.
- Registered `model:generate` and `db:create` under a new `[pkg-db]` section
  ("Database") in `cfg/cmd.ini`; the section is skipped when it resolves to no
  commands, so it is invisible without `strukt/ar`.
- Framework does **not** gain a hard dependency on `strukt/ar`; the integration
  is detected at runtime.

## Why

`strukt/ar` ships its own `dbcli` binary, but its commands were unreachable from
a framework application's `vendor/bin/strukt`, and its defaults wrote models into
`build/Models` under an `App\Model` namespace that the framework runtime
autoloader does not map. Bridging the commands makes them first-class while
keeping Ar optional.

## Documentation

- `docs/console.md`: added the `[pkg-db]` section to the `cfg/cmd.ini` example, a
  "Database (Strukt Ar)" command table with the default-target note and the
  recursive-scan caveat for `db:create`, a "Conditional commands" section
  documenting `ConditionalCommand`, and a note in "Discovery".

## Tests

- `tests/Unit/ArCommandTest.php` (5 tests): hides the commands when Ar is absent;
  lists them (and delegates `model:generate` with the application defaults) in a
  subprocess that stubs `Strukt\Ar\Model`; verifies the `ConditionalCommand`
  gate with available and missing command doubles; asserts the namespace/dir
  default resolution; and asserts a missing-namespace failure raises.

## Public API impact

- New interface `Strukt\Framework\Console\ConditionalCommand`
  (`public static isAvailable(): bool`).
- New commands `model:generate` and `db:create`.
- New console section `Database` in `cfg/cmd.ini`.
